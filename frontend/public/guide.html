Vos connexions, à votre rythme.

Orbita fonctionne sans compte externe pour gérer les projets, tâches, contacts, notes et rapports. Les intégrations sont configurées par la personne qui administre le serveur ; les clés ne sont jamais affichées dans l’application.

Activer l’assistant IA

Dans le dépôt, copiez .env.example vers .env. Choisissez ORBITA_AI_PROVIDER=openai avec une clé OPENAI_API_KEY, ou ORBITA_AI_PROVIDER=ollama avec l’adresse de votre serveur Ollama. Renseignez le modèle exact dans ORBITA_AI_MODEL.

Une fois connecté, l’assistant prépare des propositions. Seule votre validation crée les tâches. Les notes privées sont exclues du contexte automatique.

Envoyer des mails

Renseignez les paramètres SMTP et l’expéditeur dans .env. Copiez l’identifiant de votre espace depuis Paramètres vers ORBITA_SMTP_SPACE_ID. Cette connexion sera utilisable uniquement dans cet espace.

L’envoi est réservé aux administrateurs, avec relecture et confirmation. Les oppositions du CRM sont vérifiées avant envoi. La synchronisation des mails entrants n’est pas encore disponible.

Lire l’activité GitHub

Associez un dépôt sous la forme propriétaire/dépôt à un projet et cliquez sur « Lire l’activité ». La lecture publique fonctionne sans jeton. Pour un dépôt privé, configurez un jeton limité et ORBITA_GITHUB_SPACE_ID. Orbita n’effectue aucune écriture GitHub dans cette version.

Appliquer une configuration

Après modification de .env, recréez le conteneur :

docker compose up -d --build

Le guide complet de lancement, de sauvegarde et des limites de cette version est fourni dans docs/running.md et docs/delivery.md du dépôt. Cette version est un pilote local ; les parcours de commercialisation restent à compléter.
